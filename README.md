# NISA投信比較サイト 自動クローリング一式

NISA制度（つみたて投資枠／成長投資枠）対象の投資信託を毎日自動で調べ直し、
サイトに反映するための一式です。「補助金台帳」プロジェクトと同じ考え方で、
GitHubの無料機能だけで動きます（追加のデータベース契約などは不要です）。

## 全体の仕組み

```
毎日 朝6:00（日本時間）
  → GitHub Actions が起動
  → crawler/main.py が投資信託協会「投信総合検索ライブラリー」から
    NISA対象（つみたて投資枠／成長投資枠）の投資信託データと、
    それぞれの基準価額の1年推移データを取得
  → data/funds.json に保存（前回分とマージするので、
    1回の取得失敗でサイトの表示がゼロ件になることはない）
  → scripts/export_to_data_js.py が site/data.js を作り直す
    （絞り込み検索ページ index.html 用）
  → scripts/generate_pages.py が以下を作り直す
    （検索エンジン対策・JavaScript不要でも読める静的ページ）
      - site/funds/<ISINコード>.html … ファンドごとの詳細ページ＋基準価額チャート
      - site/list/page-N.html         … 100件ずつの静的な一覧ページ
      - site/sitemap.xml, site/robots.txt
  → 変化があれば自動的にリポジトリへコミット
  → GitHub Pagesに自動で公開し直す
```

## サイトの機能

- キーワード検索（商品名・運用会社名）
- 信託報酬率／1年リターン／騰落率(3年) をプルダウンの範囲指定で絞り込み（組み合わせ可）
  ※ スマートフォンでも操作しやすいよう、具体的な数値を自分で入力しなくても選べる、あらかじめ区切った範囲から選ぶ方式にしています。
- NISA区分（つみたて投資枠／成長投資枠）での絞り込み
- 各列見出しクリックでの並び替え（初期状態は **1年リターンが高い順→（同水準の場合は）信託報酬率が高い順**）
- 一覧の各ファンド名のすぐ下にある「チャートを見る」リンクから、そのファンドの詳細ページ（基準価額・純資産総額・目論見書リンク・直近1年間の基準価額推移チャート・ネット証券各社へのリンクなど）を見られる
- 一覧（絞り込み検索ページ・静的一覧ページとも）は商品名・信託報酬率・1年リターン・騰落率(3年)のみを表示するシンプルな構成にし、運用会社・基準価額・純資産総額・目論見書はファンド詳細ページに集約しています（スマートフォンでの表示を優先した構成）。

## 検索エンジン対策（SEO）について

`site/index.html` はJavaScriptでdata.jsを読み込んで表の中身を描画する
「アプリ的」なページなので、検索エンジンによっては本文が読み取られない
おそれがあります。そこで、`scripts/generate_pages.py` が **ファンドごとの
詳細ページ（`site/funds/`）と、100件ずつの静的な一覧ページ
（`site/list/`）を、HTMLソースに直接テキストとして書き出す形で**
別途生成しています。これらのページはJavaScriptなしでも内容がすべて
読めるので、検索エンジンのクローラーにも人が閲覧する場合にも情報が
渡ります。`site/sitemap.xml` にすべてのURLを列挙しているので、
検索エンジンが見つけやすくなっています。

`index.html`（絞り込み検索）と `site/list/page-1.html`（静的一覧）は
相互にリンクしています。用途に応じて使い分けてください。

## データの取得元と、正直な注意点

- 商品名・基準価額・信託報酬率・純資産総額・騰落率(1年/3年)・分配金利回り
  算出用データ・目論見書PDFリンク・運用会社名・NISA区分・基準価額の1年推移は、
  投資信託協会（資産運用業協会）が運営する **「投信総合検索ライブラリー」**
  （https://toushin-lib.fwg.ne.jp/FdsWeb/FDST999900 ）のデータを使っています。
  国内でほぼ全ての追加型公募投信を横断的にカバーしている、業界団体による
  公開情報です。
- **叩いているのは検索ページ・詳細ページ自身が内部的に使っているAJAX用の
  エンドポイント**であり、外部利用者向けに公式ドキュメント化された公開APIでは
  ありません（2026年8月時点で robots.txt による明示的な禁止は確認していません）。
  そのため、
  - 1日1回程度の穏やかな頻度でのみ呼び出す
  - リクエストの間に約0.35〜0.4秒の間隔を空ける
  という配慮をしています（`crawler/fetch_toushin_lib.py`）。もし将来
  サイト側の仕様変更で取得できなくなった場合は、投信総合検索ライブラリーの
  ページのJavaScript（`/static/js/web/FDST9999/FDST999900.js`,
  `/static/js/web/FDST0300/FDST030000.js` 等）を見ながら、リクエストの形を
  調整する必要があります。
- **1日あたりのリクエスト数について。** 一覧取得に約130回、
  ファンドごとの基準価額チャート取得に約2,600回（＝対象ファンド数と
  ほぼ同数）の合計、1日あたり約2,700回のリクエストを投げます。
  1回あたり0.35〜0.4秒の間隔を空けているため、クローリング全体で
  30分前後かかります。GitHub Actionsの無料枠（パブリックリポジトリなら
  実質無制限）の範囲内ですが、対象サイトへの負荷という観点でも
  「1日1回」の頻度は変えないことをおすすめします。
- **月間販売金額は掲載していません。** 個別ファンド単位で市場全体の
  月間販売金額を無料公開している公式データソースが見当たらなかったため、
  今回のスコープからは除外しています。
- **運用会社サイトへのリンクは、目論見書PDFが置かれているドメインから
  機械的に推定したもの**です（例：目論見書が `https://www.example-am.co.jp/...`
  にあれば、運用会社リンクは `https://www.example-am.co.jp/` になります）。
  正しく開けない場合があります。
- 確定拠出年金専用投資信託など一部のファンドは、目論見書PDFが
  投信総合検索ライブラリーに掲載されていないため、目論見書リンクが
  「—」になります。同様に、設定から日が浅いファンドは1年分のチャートが
  作れない（点数が少ない）ことがあります。
- **リポジトリの容量について。** ファンドごとの詳細ページ（約2,600ページ）は
  基準価額チャートを含めて毎日まるごと再生成・再コミットされます。
  1ファンドあたり数KB程度に抑える設計にしていますが、日々コミットが
  積み重なるため、リポジトリの履歴サイズは時間とともに増えていきます。
  数年単位で運用する場合は、GitHubの無料枠（リポジトリ容量の目安）を
  たまに確認することをおすすめします。増えすぎた場合は、過去のコミット
  履歴を整理する（`git gc` や履歴の圧縮）といった対応が必要になる
  可能性があります。

このデータはあくまで参考情報です。投資判断の際は、必ず各ファンドの
目論見書・運用報告書など公式資料をご確認ください。

## 必要なアカウント

- **GitHubアカウント**（無料）。これだけです。
- サイトを公開するには **GitHub Pages**（GitHubに無料で付いている機能）を
  使います。「site」フォルダのような任意のフォルダを公開するために、
  GitHub Actions経由でのデプロイ方式を使っています
  （`.github/workflows/daily-crawl.yml` に処理が入っています）。

## セットアップ手順

### 1. GitHubにリポジトリを作る

GitHubで新しいリポジトリを作成し（例: `nisa-fund-compare`）、この
フォルダの中身をすべてアップロードしてください。

やり方が分からない場合は、Claude（Claude Code）に
「このフォルダをGitHubの新しいリポジトリにアップロードして」と
頼めば、コマンドを実行して代わりに進めることができます
（ただしGitHubアカウントへのログイン・認証だけはご自身の操作が必要です）。

### 2. GitHub Pagesの公開方法を「GitHub Actions」に設定する

リポジトリの Settings → Pages を開き、「Build and deployment」の
「Source」を **「GitHub Actions」** に設定してください
（「Deploy from a branch」ではなく、こちらを選ぶ必要があります。
「site」フォルダはワークフローがビルド成果物として自動的に
アップロードするので、ブランチ・フォルダ指定は不要です）。

### 3. GitHub Actionsを有効にする

特別な操作は不要です。`.github/workflows/daily-crawl.yml` が
入った状態でリポジトリにアップロードするだけで、GitHub側が
自動的に「毎日この時間に実行する」設定を認識します。

リポジトリの「Actions」タブを開くと、実行結果（成功・失敗）を
確認できます。

### 4. （任意）今すぐ1回試してみる

GitHubの「Actions」タブ →「毎日のNISA投信データ更新」→
「Run workflow」ボタンで、スケジュールを待たずに今すぐ1回実行できます
（初回は基準価額チャートの取得も含めて30分前後かかります）。

実行が成功すると、`https://（あなたのアカウント名）.github.io/（リポジトリ名）/`
のようなURLでサイトが公開されます（URLはリポジトリの Settings → Pages
にも表示されます）。

## ファイル構成

```
nisa-fund-compare/
├── crawler/
│   ├── schema.py             # 1件分のデータの形（型）の定義
│   ├── fetch_toushin_lib.py  # 投信総合検索ライブラリーからの取得ロジック
│   └── main.py                # 全体をまとめて実行するスクリプト
├── scripts/
│   ├── export_to_data_js.py  # JSON → 絞り込み検索ページ用データ（data.js）
│   └── generate_pages.py     # JSON → SEO用の静的ページ（ファンド詳細・一覧・sitemap）
├── data/
│   └── funds.json             # 取得済みデータ本体（NISA対象 約2,600本、基準価額の1年推移込み）
├── site/
│   ├── index.html             # 絞り込み検索ページ（JavaScript）
│   ├── data.js                  # index.htmlが読み込むデータ（自動生成）
│   ├── style.css                # 静的ページ用スタイル（自動生成）
│   ├── sitemap.xml              # 検索エンジン向けのURL一覧（自動生成）
│   ├── robots.txt               # クロール許可設定（自動生成）
│   ├── funds/<ISINコード>.html  # ファンドごとの詳細ページ＋チャート（自動生成）
│   └── list/page-N.html         # 静的な一覧ページ・100件ずつ（自動生成）
├── .github/workflows/
│   └── daily-crawl.yml        # 「毎日自動実行してGitHub Pagesに公開して」という設定ファイル
└── requirements.txt            # 必要なPythonライブラリの一覧（requestsのみ）
```
